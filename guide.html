Reconciliation Standard Operating Procedure (SOP) & Reference

This guide provides step-by-step operational instructions, status definitions, and Excel output specifications for reconciling CMS (Master) records against Back Office transaction logs. All processing executes locally inside your browser for 100% data privacy.

Step 01

Upload Source Files

Upload the master CMS Excel file and the Back Office export separately (`.xlsx`, `.xls`, or `.csv`).

Step 02

Map Columns & Filter

Select the active worksheet, header row index, Key (Approval Code), Date, and Amount columns. Apply optional scope filters.

Step 03

Configure Tolerance

Set the date-mismatch window (default: 60 minutes) to automatically handle midnight cut-off posting delays.

Step 04

Verify & Export

Confirm the row-count integrity check (Output Rows = CMS Rows) and download the color-coded multi-sheet Excel report.

Reconciliation Status Matrix

Status Code Condition / Rule Recommended Action
MATCHED Key, calendar date, and transaction amount match identically. No action required. Cleared for settlement.
CMS_ONLY Present in CMS master file but missing in Back Office logs. Investigate missing settlement or raise dispute ticket with evidence.
BACKOFFICE_ONLY Recorded in Back Office but absent from CMS master file. Verify off-system adjustment, reversal, or unposted entry.
AMOUNT_MISMATCH Key and date match, but transaction amounts differ. Check partial refunds, fee deductions, or chargeback adjustments.
DATE_MISMATCH Key and amount match, but timestamp exceeds tolerance window. Validate next-day T+1 batch settlement cut-off.
DUPLICATE Multiple occurrences of the same unique key detected. Audit for double-posting or retry duplication.
REVIEW_REQUIRED Ambiguous key/amount combination requiring manual verification. Perform manual ledger trace before closing batch.
